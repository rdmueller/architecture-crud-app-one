== Deployment-Varianten

=== Variante 1: Lokale Installation

**Komponenten**:
* Python 3.10+ Installation
* Virtuelle Python-Umgebung
* Installierte Dependencies (requirements.txt)
* Lokales Dateisystem für JSON-Speicherung

**Start-Kommandos**:
```bash
# FastAPI starten
python run_api.py
# oder mit Dateninitialisierung
python run_api_with_data.py

# Streamlit starten (in separatem Terminal)
python run_ui_with_data.py
# oder manuell
streamlit run src/ui/app.py
```

=== Variante 2: Docker-Container

**Komponenten**:
* Docker Engine
* Docker Compose
* Volume-Mount für JSON-Persistenz

**Docker-Compose Konfiguration**:
```yaml
version: '3.8'
services:
  api:
    build: 
      context: .
      dockerfile: Dockerfile.api
    ports:
      - "8082:8082"
    volumes:
      - ./data:/app/data
    environment:
      - ARCHITECTURE_DATA_FILE=/app/data/architecture.json
  
  ui:
    build:
      context: .
      dockerfile: Dockerfile.ui  
    ports:
      - "8501:8501"
    depends_on:
      - api
    environment:
      - API_URL=http://api:8082
```

=== Variante 3: Dokumentations-Pipeline

**Komponenten**:
* GitHub Repository
* GitHub Actions Workflow
* docToolchain (Docker Container)
* GitHub Pages

**Workflow**:
1. Entwickler pusht Änderungen
2. GitHub Actions triggert
3. docToolchain generiert Dokumentation
4. Dokumentation wird auf GitHub Pages deployed

```yaml
# .github/workflows/publish-docs.yml
name: Publish Documentation
on:
  push:
    branches: [main]
    paths:
      - 'docs/**'
      - 'docToolchainConfig.groovy'
```

== Infrastruktur-Anforderungen

[cols="1,3,2", options="header"]
|===
| Komponente | Anforderung | Begründung
| CPU | 2+ Cores | Parallele Verarbeitung von UI und API
| RAM | 4 GB minimum | Python-Prozesse und Daten-Caching
| Speicher | 1 GB | Anwendung + JSON-Daten
| Netzwerk | Port 8082, 8501 | API und UI Zugriff
| OS | Windows/Linux/macOS | Python-Kompatibilität
| Docker | Optional | Für containerisiertes Deployment
| Internet | Erforderlich | Für GitHub Pages und Dependencies
|===

== Sicherheitsüberlegungen

* **Netzwerk**: Standardmäßig nur lokaler Zugriff (localhost)
* **Dateizugriff**: Beschränkt auf konfiguriertes Datenverzeichnis
* **Authentifizierung**: Keine (nur für lokalen/internen Gebrauch)
* **HTTPS**: Optional über Reverse-Proxy konfigurierbar
* **GitHub Pages**: Öffentlich zugängliche Dokumentation
* **Secrets Management**: Umgebungsvariablen für sensible Konfiguration

== Skalierungsoptionen

Für zukünftige Erweiterungen:

1. **Horizontal**: Load Balancer vor mehreren API-Instanzen
2. **Vertikal**: Mehr CPU/RAM für größere Datenmengen
3. **Datenbank**: Migration von JSON zu echtem Datenbanksystem
4. **Caching**: Redis für Session-Management und Caching
5. **CDN**: Für statische Assets und Dokumentation
6. **Container-Orchestrierung**: Kubernetes für komplexere Deployments

== Monitoring und Logging

* **Anwendungslogs**: Strukturierte Logs via Python logging
* **Access Logs**: FastAPI/Uvicorn Access-Logs
* **Error Tracking**: Exception-Handling mit Stack-Traces
* **GitHub Actions**: Build- und Deployment-Logs
* **Healthchecks**: `/health` Endpoint für Monitoring

== Backup und Recovery

* **Daten-Backup**: Regelmäßige Sicherung der JSON-Dateien
* **Versionskontrolle**: Git für Code und Dokumentation
* **Disaster Recovery**: Wiederherstellung aus Git + Backup
* **Rollback**: Über Git Tags und Releases
